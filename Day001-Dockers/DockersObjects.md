# Docker Objects & Images Guide

## 1. Introduction

Docker operates using several core foundational objects. The most essential of these are **images, containers, networks, and volumes**. 

An **image** acts as the immutable (read-only) template or blueprint from which operational containers are deployed.

---

## 2. Core Docker Objects Flow

**Docker System**
├──> **Images:** Read-only application templates
├──> **Containers:** Running, active instances of images
├──> **Networks:** Bridges facilitating container communication
└──> **Volumes:** Decoupled persistent data storage

---

## 3. Docker Image Architecture

An image packages everything required for execution: application code, libraries, system tools, and runtime configurations.

### Layered File System

**Docker Image Architecture**
├──> **Writable Layer:** (Container Only - Runtime modifications)
├──> **Application Layer:** Custom configuration and files
├──> **Dependency Layer:** Libraries and packages
└──> **Base Layer:** Core OS filesystem (e.g., Alpine, Debian)

> **Efficiency Note:** Docker caches and reuses identical shared read-only layers across multiple different images to save local storage and download bandwidth.

### Container Writable Layer & Copy-on-Write

When a container launches from an image, Docker mounts a **thin, ephemeral Writable Layer** on top of the stacked read-only image layers. 
* All file modifications or new data created during runtime are saved to this Writable Layer.
* If a container needs to modify a file from a lower read-only layer, Docker uses **Copy-on-Write (CoW)** to copy that specific file up into the Writable Layer for modification, leaving the original layer untouched.

## 4. Key Image Operations & Commands

| Operation | Command | Purpose |
| :--- | :--- | :--- |
| **Search** | `docker search <query>` | Find images on Docker Hub |
| **Pull** | `docker pull <image>:<tag>` | Download image to local host |
| **List** | `docker images` \| `docker image ls` | View locally available images |
| **Inspect** | `docker image inspect <image>` | View detailed JSON metadata |
| **History** | `docker image history <image>` | View ordered build layers |
| **Tag** | `docker tag <source> <target>` | Assign alias/version tag to image |
| **Remove** | `docker image rm <image>` | Delete local image |
| **Clean** | `docker image prune -a` | Delete all unused images |

---

## 5. Architectural Terms Dictionary

| Concept | Explanation |
| :--- | :--- |
| **Layer** | A discrete filesystem change generated by a single build instruction |
| **Writable Layer** | Ephemeral top layer where active container state changes are stored |
| **Copy-on-Write** | Optimization strategy that copies files upward only when modified |
| **Storage Driver** | Underlying engine that stacks layers and manages the unified view |
| **Tag** | Semantic version identifier assigned to an image repository |

---

## Key Takeaways

* **Image:** The static, layered blueprint.
* **Container:** The dynamic, running instance with a writable top layer.
* **Layers:** Reusable, shared filesystem diffs that optimize storage.
* **Writable Layer:** Temporary storage destroyed when the container is deleted (unless volumes are used).
